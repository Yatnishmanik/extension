# 📈 @verification-before-completion

## 📌 Overview
- **Trigger**: `@verification-before-completion`
- **Category**: General Productivity & Workflow (For Both)
- **Purpose**: Perform rigorous checks, linting, tests, and reviews before handing in an assignment or merging a Pull Request.
- **Best For**: Guaranteeing zero-defect deliverables, perfect code compilation, and flawless formatting.

---

## 🚀 How to Trigger
In your Promptimity AI chat, type:
```text
@verification-before-completion [provide the completed code, essay text, or repository files to verify]
```

---

## 💡 Key Capabilities & Features

- **Multi-Point Verification Checklist**: Automatically builds a custom verification plan based on your exact assignment rubrics or project requirements.
- **Lint & Syntax Audit**: Scans code for hidden bugs, syntax exceptions, formatting errors, unused variables, and logical flaws.
- **Edge-Case Stress Testing**: Proposes concrete test inputs, extreme values (e.g. empty inputs, negative numbers, ultra-long strings) to verify robustness.
- **Accessibility & SEO Verification**: Audits web pages for semantic elements, unique interactive IDs, fast load strategies, and screen-reader friendliness.
- **Plagiarism & Tone Review**: Analyzes essay drafts or reports to ensure perfect academic honesty, accurate referencing, and formal tones.

## 🛠️ Real-world Examples

### Example 1: Pre-Release PR Review
**Prompt:**
> `@verification-before-completion I have completed the registration page feature in our codebase. Let's audit the code for hidden edge cases, run lint validation, test it for database transaction errors, and verify responsive CSS.`

### Example 2: Checking a University Essay
**Prompt:**
> `@verification-before-completion I have finished writing my history essay on the industrial revolution. Let's run a rigorous proofread for grammatical correctness, formal tone, bibliography format, and verify it perfectly meets these requirements.`

---

## 📘 Best Practices
1. **Never Assume It Works**: Just because the app builds doesn't mean it handles edge cases. Always test extreme parameters and invalid inputs.
2. **Review accessibility (A11y)**: Make sure all buttons, forms, and images have proper labels, alt text, and semantic HTML elements.
3. **Draft a Walkthrough**: After verifying your work, write a brief, clean walkthrough of what was tested and how it succeeded to present to your teacher or reviewer.
